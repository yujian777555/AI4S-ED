## 0. 文档说明

- **定位**：给出「用户研究主题 → 可检索、可引用、反幻觉的知识资产」的端到端工程设计，包括：调研（lit_researcher）→ 解析（元数据/全文/表格/图表/公式）→ 抽取（EDDO 结构化断言）→ 策审入库（knowledge_curator）→ **反幻觉检索问答侧设计** → 更新与增量治理；并明确与 02/04/05/07 的接口边界。
- **读者**：文献/知识管线开发工程师、领域科学家（抽检与术语把关）、智能体平台工程师（DSH 编排）。
- **内部产物命名**：本文引入的流水线中间产物（RetrievalReport/ParsedDoc/TableObject/ChartObject/AssertionSet/CurationReport 等）为**实现级工件名**，不进入 01 附录 A 的对外产物命名空间；其 JSON Schema 在 08 §3.2 的模式注册中心登记版本化，对外统一封装为 USDO。
- **成功判据（对齐 08 §5 M1）**：单篇入库成本 < 2 min；问答“可引用率”≥ 90%；幻觉率从 MVP 起基线化并持续下降；抽取断言抽检通过率 ≥ 95%。

## 1. 总览：从研究主题到反幻觉知识资产

闭环①的本质是**把不可检索、不可校验、版权受限的外部文献，转成可检索、可引用、可版本回滚的内部结构化知识**。平台在 L1（接入采集）与 L2（知识层）之间部署一条四阶段流水线，任何阶段都携带 `trace_id + provenance_id`（01 §4.1）以便回溯与审计。

```
用户研究主题 / 科研目标（orchestrator 下达，或用户在文献任务台直接发起）
        │
        ▼
┌──────────────── 阶段A 调研 · lit_researcher（L4 Agent + L1 适配器）───────────────┐
│  主题 → EDDO 概念扩展（膜材料/离子/工况/指标/过程）→ 中英多组检索式                 │
│  → 跨源检索(Crossref/OpenAlex/arXiv/S2/Google Patents/国知局/标准/CNKI·万方·维普) │
│  → 去重(DOI/title 归一) → 相关性评分 → RetrievalReport（排序+coverage 缺口+冲突标注）│
└──────────────────────────────────────────────────────────────────────────┘
        │ （仅元数据+摘要+机构订阅链接/OA 指针落库，全文副本不入私有库）
        ▼
┌──────────────── 阶段B 解析 · 解析工人/队列（L1）──────────────────────────────────┐
│  GROBID：元数据/参考文献→DOI 解析    MinerU/Nougat：PDF→结构化文本(保留页码)         │
│  表格→TableObject(行列/单位/校验)    图表→ChartObject(类型/轴变量/单位/数字化)       │
│  公式→LaTeX+符号归一（EDDO 符号注册表）→ ParsedDoc（A~E 质量分级）                  │
└──────────────────────────────────────────────────────────────────────────┘
        │
        ▼
┌──────────────── 阶段C 抽取 · schema-guided DeepSeek（L4 工具）────────────────────┐
│  文本/TableObject/ChartObject → EDDO 结构化断言 AssertionSet：                    │
│  (subject, property, value+unit, 工况绑定[], 出处{文献ID+页码/对象ID}, confidence) │
│  JSON Schema 校验 → 反例修复循环 → 无单位/缺工况自动降级，歧义消解与同义归一         │
└──────────────────────────────────────────────────────────────────────────┘
        │
        ▼
┌──────────────── 阶段D 策审入库 · knowledge_curator（L4）─────────────────────────┐
│  完备性检查 → 冲突检测(与既有图谱断言比对→一致/工况差异/冲突→挂起人工/真值判定)      │
│  → 质量评分(与 01/02 的 quality/confidence 对齐) → 原子入库 + 版本快照              │
│  落库三载体：图谱断言/元数据记忆(SQLite) + 向量(FAISS) + 载荷(本地文件)   │
│  + 时序原始数据以文件/parquet 归档 + SQLite 元数据（不单独设时序库）                     │
└──────────────────────────────────────────────────────────────────────────┘
        │
        ▼
   L2 知识资产：可检索、可引用、可溯源 —— 每条声明可回指
   (证据类型∈{文献|图谱|仿真|实验}, ref_id, 定位=页码/图表对象ID/USDO ID, confidence)
        ▲
        │ 消费方：反幻觉检索问答（本文 §6）、闭环② RADE（05）、闭环④ 自进化（07）、
        │       模型训练语料（04）、案例库比对（06/07）
```

**阶段职责与执行者**

| 阶段 | 执行者 | 对应 01 分层 | 输入 → 输出（实现级工件） |
|---|---|---|---|
| A 调研 | `lit_researcher` + 检索适配器 | L4 + L1 | ResearchTopic → RetrievalReport（含 DocumentCandidate[]） |
| B 解析 | 解析队列（定时/事件驱动） | L1 | DocumentCandidate（PDF/XML/LaTeX）→ ParsedDoc |
| C 抽取 | schema-guided DeepSeek 抽取器（LLM 工具） | L4（调 L3 无关） | ParsedDoc → AssertionSet |
| D 策审入库 | `knowledge_curator` | L4 → L2 | AssertionSet → CurationReport + 原子提交快照 |
| 消费 | 检索问答/RADE/评测 | L2/L3/L4/L6 | 见 §6~§8 |

**贯穿性设计原则**

1. **全文不落私有库**（版权合规第一原则，见 §2.3）：私有库只持久化「元数据 + 摘要 + 结构化抽取结果」；全文仅在解析瞬间于内存流中处理，需要时以机构订阅链接/OA 直链形式呈现给用户；
2. **对象化优先**：表格/图表/公式不混在纯文本里切碎，先对象化（TableObject/ChartObject/公式块）再抽取，保住数值语义与证据定位（页码 + 对象 ID）；
3. **分级而不丢弃**：低质量解析不静默丢文献，按 A~E 分级（可用/降权/人工/弃用/拒收），人工抽检口（L0 文献任务台 + 策审台）兜底；
4. **声明级信任**：入库断言一律携带单位、工况绑定与出处，`confidence ∈ {verified, high, medium, hypothesis}`，仅 verified/high 可参与事实推理（01 A.6）——这是「反幻觉」的第一道闸门，在**入库时**就杜绝无证据/无单位数值进入事实面；
5. **原子提交 + 版本快照**：一批文献的图谱/向量/USDO 更新在同一事务边界内完成，可整体回滚（01 §4.4），下游消费方只读已提交版本。

## 2. 调研 Agent：lit_researcher

### 2.1 输入输出契约

| 项 | 说明 |
|---|---|
| 输入 | `ResearchTopic`（主题句+细分场景标签）、时间窗、语种、是否含专利/标准、预算与许可约束、用户偏好文献（正/负反馈种子）；由 orchestrator 从会话意图解析或用户在文献任务台直接编辑 |
| 输出 | `RetrievalReport`：按相关度排序的 `DocumentCandidate[]`（含来源、元数据、摘要、链接、相关分、被引、获取等级）、去重统计、**coverage 缺口矩阵**、**冲突主题标注**、下一轮检索建议 |
| 校验 | RetrievalReport JSON Schema 注册于模式注册中心（08 §3.2），schema 校验不通过自动修复或中止 |

### 2.2 检索源矩阵（中英文全覆盖）

适配器统一实现「限流/重试/鉴权/原始返回快照/字段归一」五件事；字段名以本表“可获得字段”为最终落库口径，源内字段先归一化。

| 数据源 | 类型/语种 | 接口形态 | 可获取元数据字段 | 全文/摘要可及性 | 用途与合规要点 |
|---|---|---|---|---|---|
| Crossref | 期刊/图书 DOI 注册中心（全球） | REST API | DOI、题名、作者(含 ORCID)、期刊、卷期页、年、出版者、license、部分摘要、**参考文献 DOI 列表** | 摘要不全；无全文 | DOI 权威校验与去重主键、参考文献 DOI 解析（引文网络）；限速缓存受限字段 |
| OpenAlex | 学术作品聚合（多语） | REST API | work id、DOI、题名、作者+机构+国家、concepts(学科)、keywords、**可重建摘要(inverted index)**、cited_by_count、类型、年份、**OA 直链** | 摘要基本齐全；OA 全文直链 | 主检索源、被引加权、学科/概念覆盖分析；OA 判断依据 |
| arXiv | 预印本（英） | API v2 + 源文件 | id、题名、作者、摘要、分类、版本序列、关联 DOI | 全文 TeX/PDF 可下载（OA） | 快速通道（新工作/数据可用），版本演进跟踪 |
| Semantic Scholar | 论文+引用图谱（英） | Graph API | paperId、题名、摘要、tldr、作者、fieldsOfStudy、**citationCount / influentialCitationCount**、openAccessPdf、externalIds(DOI/arXiv) | OA PDF 指针 | 引用影响力加权、同断言多源共证检索 |
| Google Patents / Lens（聚合） | 专利（美/中/EP/PCT…） | 页面/聚合 API，建议经 Lens 或 OpenAlex patents 聚合 | 公开号、题名、专利权人、申请/公开日、IPC/CPC、摘要、部分权利要求可读 | 权利要求/说明书网页可读 | 专利地图（膜/工艺专利族）、规避与 FTO 前调研 |
| 国家知识产权局检索系统 | 中国专利 | 机构渠道/批量导出受限 | 公开号/申请号、名称、申请人、IPC、中文摘要 | 著录项可读 | 中文专利覆盖；合规批量导出以机构协议为准 |
| 标准数据库（国标全文公开系统/ISO·IEC 等机构订阅） | 标准 | 机构订阅/公开系统 | 标准号、中英名称、发布/实施日期、代替关系、范围、部分技术条款 | 强制性国标全文公开，其余多为在线预览 | ED 测试方法/术语标准的权威出处，测样与判据引用 |
| CNKI / 万方 / 维普 | 中文期刊/学位/会议 | **机构合规接口**（CARSI/机构漫游/镜像/签约 API） | 篇名、作者、机构、摘要、关键词、期刊、卷期、基金、部分 DOI | **全文仅机构内合法阅读** | 中文文献主覆盖；只取元数据+摘要+机构订阅链接，全文不抓取不落库 |
| 出版社 OA/订阅（Elsevier/Springer/Wiley/ACS/RSC/IOP…） | 期刊全文 | DOI 跳转 + 机构 IP/CARSI + Unpaywall 聚合 | 出版社题录 | OA 篇目全文可解析；订阅篇目机构内可读 | 订阅全文仅“读后即弃”解析（见 2.3 C 档） |

> 分工说明：英文与预印本以 OpenAlex+Crossref+arXiv+S2 为主力；中文以 CNKI/万方/维普（合规接口）为主力；专利走 Google Patents/Lens + 国知局；标准走标准库。PubMed 类生物医学源不在 ED 主场景，不默认接入（需要时经 OpenAlex 已覆盖索引）。

### 2.3 版权合规策略（全文不落私有库）

**总原则**：私有知识库**永不保存可重建原文全文的副本**；落库内容 = 元数据 + 摘要 + 「自提取的结构化数据（数值断言、数字化曲线点、图元数据、短引用片段）」。全文始终留在外部版权方一侧，平台只持有合法访问指针与结构化抽取物。

| 数据档 | 定义 | 可持久化到私有库 | 不可持久化 |
|---|---|---|---|
| A 档 元数据级（所有源默认） | 题录/摘要/关键词/学科/引用数/链接 | 全部元数据 + 摘要 | — |
| B 档 OA 全文（CC 许可 / arXiv / 机构自产 OA） | 许可明确允许再分发或平台已获授权 | 元数据 + 解析出的结构化文本分块 + 表格/数字化数据（**许可含 CC-BY 等再分发条款时**；否则按 C 档处理） | 超出许可范围的原文拷贝 |
| C 档 订阅全文（机构合法访问） | 经机构 IP/CARSI 合法在线阅读 | 元数据 + 摘要 + 自提取断言/表格数值/图元数据 + 不可重建全文的短引用 | 全文 PDF/整段文字副本/原图拷贝 |

细化规则：

1. **解析即弃**：C 档全文只在内存流中完成 GROBID/MinerU 解析，进程结束即弃，不写对象存储；解析产物（结构化文本）仅保留「断言级摘编 + 证据定位元数据（页码/坐标/对象 ID）」，不做整篇文本持久化。若确有合法保存全文的需求（机构自购数字馆藏且授权允许），对象存储文件须打 `access_policy=institutional-only` 标记 + 加密 + 访问审计，默认关闭，需管理员显式开启（08 §8 合规风险对策）。
2. **图表对象不存原图**：图表只存「图元数据（类型/轴变量/单位/数值范围）+ 数字化数据点 + 低维视觉特征向量」。特征向量与数字化点**不可逆重建原图**，规避图像复制风险；原图在用户侧通过机构订阅链接查看。
3. **引用呈现**：检索与问答结果中的“查看原文”一律跳转 DOI/出版社/OA 直链/机构数据库页，由用户凭机构权限访问。
4. **合规自检清单**（每个适配器上线前过一遍并写入代码注释与 README）：源 ToS 允许的缓存字段与期限；API 速率上限与休眠策略；批量导出是否超出许可；抓取是否只针对元数据页；涉密/受控文献（如内部报告）不进调研池；中文库机构协议覆盖范围记录在案（08 §8）。

### 2.4 检索式自动构造（主题词 + EDDO 概念扩展）

lit_researcher 将主题词沿 **EDDO 概念维度**展开后组合成多组 query，兼顾**召回**（宽 query 集）与**精度**（主题交集 query），中英文分别构造。

**EDDO 概念扩展维度（电渗析）**

| 维度 | 示例概念（EDDO 类/个体） | 同义/变体（构造用） |
|---|---|---|
| 过程 | 电渗析 ED、倒极电渗析 EDR、双极膜电渗析 EDBM/BMED、选择性电渗析 SED | electrodialysis, reversal, bipolar membrane, selective, 双极膜法 |
| 对象/应用 | 海水淡化、高盐/浓盐水处理、酸碱回收、卤水提锂、物料提纯、废酸废碱资源化 | desalination, brine, acid/base regeneration, lithium recovery |
| 指标 | 能耗、电流效率、极限电流密度、脱盐率、水回收率、膜污染、膜寿命、选择透过性 | energy consumption, current efficiency, limiting current density, fouling |
| 材料 | 离子交换膜(均相/异相)、双极膜、阳/阴离子交换膜、复合膜、Nafion/Neosepta/商品膜族 | IEM, CEM/AEM, BPM, PFSA, membrane |
| 工况 | 温度、浓度、流速/雷诺数、电流密度、电压、回收率目标 | temperature, concentration, current density, flow rate |

**检索式构造算法（伪代码）**

```
1. 主题词 → EDDO 概念映射（resolver 见 §4.3），得到 {主题概念集 T, 维度概念集 D1..D5}
2. 生成 query 集 Q：
   Q_recall = 每个维度概念单独成词/短语 + 过程同义词集（如 "bipolar membrane electrodialysis" OR "BMED" OR "双极膜电渗析"）
   Q_precision = T × 关键维度（过程 ∧ 对象 ∧ (指标|材料|工况)），如
                 ("electrodialysis" AND ("acid" OR "base") AND ("energy" OR "current efficiency"))
   每个概念附 同义扩展(§4.3 词表) 与 语种标记(zh/en)
3. 跨源执行：每源取 Q 子集并施源内过滤（年份/类型/语种），OpenAlex/arXiv/S2 走布尔 query 语法，
   CNKI 走合规接口的检索词（可查询同字段）
4. 速率合规：并发 ≤ 源限流 80%，失败退避重试(2/8/30s)，原始返回存快照桶（审计）
```

### 2.5 去重（DOI/title 归一）与相关性评分

**去重归并**

| 信号 | 规则 | 归并策略 |
|---|---|---|
| DOI | 大写归一、去掉 DOI 后的版本后缀（区分 pre-print DOI 与 journal DOI）；与 arXiv/PMC 的 externalIds 交叉核对 | 同一 DOI 只保留**可信度最高**来源记录为主记录（出版社/OpenAlex 优先），其余作为副记录挂接 |
| title | NFKC 归一、小写、去标点与多余空白、剥离“(Research Article)”类括号附注 | 完全一致即合并；向量相似度 ≥ 0.95 作为 fuzzy 命中进入人工确认池 |
| 版本链 | arXiv v1..vN + 期刊已发表版 | 以已发表版为主记录，arXiv 版本折叠进 `versions[]`，知识取**终版**语义并保留时间线 |
| 中文繁简/异名 | 繁简转换 + 期刊名/机构名别名表 | 归一后比对 |

**相关性评分（候选排序）**

```
score(d) = 0.45·sim_vec(embed(query), embed(title+abstract))          # BGE-M3 双语向量
         + 0.20·sim_meta(q, d)                                         # 关键词/学科/作者单位/期刊命中率
         + 0.20·norm_log_cited(d)                                      # log1p(cited_by)/log1p(c_max)，S2/OpenAlex 引用数
         + 0.10·recency(d)                                             # 近 5 年线性衰减→新文献微升
         + 0.05·rule_bonus(d)                                          # 综述/领域顶刊/用户正反馈文献引用过 各 +Δ
```

- 阈值与权重可配（每细分领域包一份 profile）；低于阈值的候选不进入下一阶段，但其元数据仍入“观察桶”供 coverage 分析；
- 排序同时输出**每个候选的命中理由**（哪个 query、哪些维度命中、为何加权），供用户与审计查看。

### 2.6 迭代调研与冲突主题标注

- **状态机**：`draft → searched → reviewed → (expanded)* → finalized`；用户在文献任务台对候选打“采纳/忽略/追问”，正负反馈进入重排权重（在线学习小模型或记忆型偏好表）；
- **coverage 缺口驱动补检索**：每轮检索后对「概念维度 × 语种 × 证据类型（实验/综述/专利/标准）」做覆盖率矩阵，低于阈值（如中文“膜污染”主题命中 < 5）即自动追加检索式并提示用户确认范围扩大；
- **冲突主题标注**：跨文献同指标数值区间**不交叠**（如某膜能耗报道 0.3~0.5 与 2~4 kWh/m³ 同单位同工况域）时，在 RetrievalReport 的 `conflicts[]` 标注并连同原文摘要展示给用户；该标注随候选流入策审冲突检测（§5.2）与问答交叉核验（§6.4），是“不产生 AI 幻觉”在调研侧的第一道显式标记；
- **成本控制**：每轮检索记录 API 成本与配额（01 L6 成本管理），超预算前向用户确认。

## 3. 解析管线：元数据 / 全文 / 表格 / 图表 / 公式

### 3.1 输入分级与路由（L1）

| 输入形态 | 首选引擎 | 说明 |
|---|---|---|
| 出版社 XML/JATS（OA 或机构授权） | 直接 XML 解析 | 最高质量：章节/表格/公式/图注天然结构化，跳过版面识别 |
| PDF（文本型） | GROBID + MinerU | 常规主流形态 |
| PDF（扫描/图像型） | MinerU（内置 OCR） | 自动降为 B~C 级信号并提示 |
| LaTeX 源（arXiv） | tex 结构化解析 | 公式无损、图表引用关系完整 |
| 纯图/无法解析 | — | 归 E 级拒收或 D 级人工 |

路由结果进入解析队列（Celery/Redis，08 §2），每个任务带 `provenance_id`。

### 3.2 GROBID：元数据与参考文献

- 输出 TEI：题名、作者（含 ORCID 若可解析）、机构、摘要、关键词、DOI、期刊/卷期页、参考文献列表（含被引文献的标题/作者/年份）；
- **参考文献 → DOI 解析**：GROBID 解析出的每一条引文用「标题+首作者+年份」去 Crossref/OpenAlex 回查 DOI，命中则记录 `citation → cited_ref_id` 边。该引用网络用于：S2 之外的引用影响力加权、综述—原始文献回溯（§4.2 secondary citation）、策审的“多源共证”分析（§6.4）；
- 字段级置信（GROBID confidence）低于阈值时标记 `field_low_conf`，供策审降权而非丢弃。

### 3.3 MinerU/Nougat：PDF → 结构化文本

| 能力 | MinerU | Nougat | 裁决策略 |
|---|---|---|---|
| 版面（多栏/标题层级/阅读序） | 强 | 一般 | 版面结果以 MinerU 为准 |
| 表格识别 | 强（区域+结构） | 一般 | 表格走 §3.4 专用管线 |
| 公式 OCR→LaTeX | 中 | **强**（端到端） | 公式以 Nougat 为主，MinerU 复核 |
| 图注/图区 | 强（检测+OCR） | — | 交给 §3.5 图表管线 |

- **页码锚点必须保留**：每个输出块带 `page_from/page_to` 与版面坐标，作为证据定位“页码/区域”的来源；无页码锚点的输出块策审时降权；
- 双引擎分歧（如同一公式两种 LaTeX、同表两种结构）记录到 ParsedDoc 的 `revision_notes`，供抽取与抽检参考，不静默二选一。

### 3.4 表格结构化与校验（TableObject）

处理链：表格区域检测 → 行列切分（处理合并单元格/多级表头/跨页表）→ 表头与单位行语义识别 → 输出 TableObject；随后做三类自动校验，任一失败即降级或转人工：

| 校验项 | 规则 | 失败处置 |
|---|---|---|
| 结构一致性 | 各数据行单元格数 = 表头列数（± 合并解释） | 重解析一次；仍失败 → C 级人工 |
| 数值可解析率 | 数据单元格数值可解析比例 ≥ 90%（含单位剥离） | 解析失败率 > 10% → 标 `table_quality=low` |
| 单位/表头识别 | 至少 70% 数值列带单位或表头含单位语义 | 无单位列整体禁止进入 verified 数值面（降 hypothesis） |

```json
// TableObject 简化 schema（全文以注册中心为准）
{
  "table_id": "T12", "caption": "Table 3. Desalination performance of ...",
  "headers": [{"col": 0, "text": "Membrane", "unit": null},
              {"col": 1, "text": "Current efficiency", "unit": "%"},
              {"col": 2, "text": "Energy consumption", "unit": "kWh/m³"}],
  "rows": [{"cells": ["AEM-A", "92.3", "1.42"]}],
  "footnote": "Operating: 25 °C, 0.05 M NaCl, 20 mA/cm²",
  "page": 6, "bbox": [12.1, 33.4, 98.2, 61.7],
  "quality": "ok"
}
```

### 3.5 图表对象化（ChartObject）与曲线数字化

**图表不是图片，是「带坐标系语义的测量载荷」**。对象化管线：

```
版面图区检测(含图注关联) → 图内文字 OCR(轴标签/图例/刻度值) → 图型分类
 → 轴变量与单位识别 → 数值范围估计 → 可数字化判定
 → (可数字化 ∧ 许可允许) 曲线数字化：轴标定→点拾取→(x,y,单位) 序列 + 拟合置信
 → ChartObject（图元数据 + 数字化序列 + 视觉特征向量）→ 挂 USDO
```

| ChartObject 字段 | 含义 | 示例 |
|---|---|---|
| chart_id / type | 图内唯一 ID / 图型 | C07 / I-V 曲线、EIS 谱、SEM 图、EDX 谱、流程图、示意、照片 |
| caption + page + bbox | 图注、页码、版面坐标（证据定位） | “Fig.5 …” / p.8 |
| axis | 轴变量名 + 单位 + 刻度范围 + 刻度类型（线性/对数） | x=电流密度 mA/cm²(0~60)，y=电压 V(0~20) |
| series[] | 数字化后的数据点 | [{"x":10,"y":3.2}, …] |
| digitizable / digitized | 是否可数字化 / 是否已数字化 | true / true |
| digit_confidence | 数字化拟合置信（决定其能否当实验数据用） | 0.96 |
| visual_vector | 低维视觉特征（图像嵌入，供图检索/去重） | [0.02, …]（不可逆原图） |
| license_note | 许可档位（§2.3） | "A/C" |

- **是否可数字化**：无坐标刻度/照片/示意 → 不可数字化，仅保留图元数据（用于检索与人工看图）；
- **数字化不确定性显式化**：每点或整序列给误差带（由轴标定与点拾取误差推导），策审时写入断言 uncertainty；
- **图型 → EDDO 消费映射**：I-V 曲线 → 04 MEM-2/3 校验与标定数据；EIS 谱 → 膜电阻/界面参数；EDX → 膜元素组成（材料实体属性）；流程图 → 工艺拓扑（流程级 EDDO）；
- 数字化产物与原图**版权隔离**（§2.3 规则 2）：原图不入库，序列数据入库。

### 3.6 公式符号归一（EDDO 符号注册表）

| 符号（归一） | 含义 | 常用单位 | 常见别称/陷阱 |
|---|---|---|---|
| J | 离子通量 | mol·m⁻²·s⁻¹ | 与质量通量区分 |
| i / j | 电流密度 | A·m⁻²（文献常用 mA·cm⁻²，换算 ×10） | 勿与虚数 i 混淆 |
| i_lim | 极限电流密度 | 同上 | 浓差极化判据（04 MEM-2 硬规则引用） |
| CE / η_CE | 电流效率 | %（分数/百分制陷阱） | 0.9 vs 90 必须归一为同一制式并记录 |
| SEC | 比能耗 | kWh·m⁻³ / kWh·kg⁻¹ 盐 | 分母基准（产水 vs 脱盐量）必须显式绑定 |
| P_sel / α | 选择透过性/分离系数 | — | 定义式因文献而异，需绑定定义 |
| z, D, μ, c, E, R_m | 价态/扩散系数/淌度/浓度/场强/膜电阻 | — | 各文献字母习惯不同 → 全文先归一再入库 |
| T, u, p | 温度/流速/压力 | K 或 ℃（换算链保留） | — |

- 归一动作：LaTeX 规范化（统一字体命令/下标写法）→ 依据符号注册表做**语义绑定**（该符号在本上下文中指哪个 EDDO 物理量）→ 同一物理量的不同字母表示（如 E 作“电压”还是“场强”）靠上下文消歧；
- 归一后的公式与其文字描述绑定成「公式-语义对」，供 04 约束校验器把文献公式声明作为可机检硬规则候选（§6.4、§8）。

### 3.7 处理失败/低质量分级（A~E）

| 级 | 含义 | 处置 |
|---|---|---|
| A | 解析完整、结构可信（锚点/校验通过） | 正常进入抽取 |
| B | 部分失败（如某表格 low、图注缺失） | 可抽取，全局 quality 降权，缺失对象不参与 verified |
| C | 需人工：低质扫描、图表无法关联、公式乱码 | 进 L0 文献任务台人工修正/标注队列；人工可改 ParsedDoc 后重抽 |
| D | 弃用：损坏文件、纯图像且 OCR 无价值、内容与主题无关 | 记录原因归档，不进知识面（可进“观察桶”供 coverage 统计） |
| E | 拒收：版权档位不允许解析（如接口仅授权元数据） | 只保留 A 档元数据 |

分级结果是 ParsedDoc 的 `quality_grade`，参与 §5.3 质量评分与检索排名惩罚。

## 4. 知识抽取与规范化（schema-guided DeepSeek）

### 4.1 抽取目标：EDDO 结构化断言

把 ParsedDoc（文本/TableObject/ChartObject/公式-语义对）抽取为**断言 Assertion**。最小完备条件（缺一不可进入 verified 面）：

```
Assertion := {
  id, ref_id,                                          // 文献/图谱/仿真/实验 源
  subject  : { eddo_class, resolved_entity, original_mention },
  property : eddo_property,                             // 含关系/属性/参数类型
  object   : { value, unit, uncertainty?, value_type }, // 数值/枚举/区间/文本
  conditions: [ {eddo_class, value, unit} ],            // 工况绑定：温度/浓度/膜型/电流密度…
  provenance: { locator: 页码|TableObject.id|ChartObject.id|公式块id, sentence? },
  claim_type: measurement | relation | method | rule | mechanism,
  source_claim_origin: primary | secondary,             // 原始实验 vs 综述转引
  confidence, quality
}
```

### 4.2 schema-guided 抽取 + JSON 校验

流程：把（schema + 术语表 + 少样本示例 + 上下文片段）注入 DeepSeek（deepseek-chat，走 DSH LLM 网关）→ 要求**仅输出 schema 化 JSON** → 注册中心 JSON Schema 校验 → 校验失败把错误信息回填再抽（≤2 次修复循环）→ 仍失败转人工或整段降级。

```json
// 抽取 schema 核心片段（JSON Schema，draft-07 风格；注册中心为权威版本）
{
  "$id": "ai4sed/assertion/v1",
  "type": "object",
  "required": ["ref_id", "subject", "property", "object", "provenance"],
  "properties": {
    "subject": {"type": "object",
      "required": ["eddo_class", "resolved_entity", "original_mention"],
      "properties": {
        "eddo_class": {"type": "string", "description": "EDDO 类，如 Membrane/CEM/AEM/BPM/ProcessED"},
        "resolved_entity": {"type": "string", "description": "消歧后实体 ID"},
        "original_mention": {"type": "string"}}},
    "property": {"type": "string", "description": "EDDO 属性/谓词，如 hasCurrentEfficiency/hasEnergyConsumption"},
    "object": {"type": "object",
      "required": ["value", "unit", "value_type"],
      "properties": {
        "value": {}, "unit": {"type": "string", "description": "SI 或标准单位；无单位必填 null 并说明"},
        "uncertainty": {"type": "number"},
        "value_type": {"enum": ["number", "range", "enum", "text", "formula"]}}},
    "conditions": {"type": "array", "items": {"type": "object",
      "required": ["eddo_class", "value", "unit"]}},
    "provenance": {"type": "object", "required": ["locator"],
      "properties": {"locator": {"type": "string", "description": "页码 / TableObject.id / ChartObject.id"},
                      "sentence": {"type": "string"}}},
    "claim_type": {"enum": ["measurement", "relation", "method", "rule", "mechanism"]},
    "source_claim_origin": {"enum": ["primary", "secondary"]}
  }
}
```

**反例与降级规则（直接决定入库 confidence）**

| 反例情形 | 判定 | 处置 |
|---|---|---|
| 数值**无单位**（“效率 0.9”） | 无法确认量纲/制式 | 标记 `missing_unit`，对象值禁止以 verified/high 入库 → 降 **medium/hypothesis** 并列原文句，抽检人工复核 |
| 有值有单位但**缺工况绑定**（无温度/浓度/膜型/电流密度任一） | 无法泛化/复现 | 降 **medium**；若连主体文献参数都缺失 → **hypothesis** |
| 含“可能/预计/推测”措辞 | 非事实断言 | **hypothesis**（只可作待验证假设引用，01 A.6） |
| 单位可换算（见 §4.4 换算表） | 归一化 | 换算到 EDDO 标准单位，双向保留原文值并记录 conversion_chain |
| 数值**违反机理量纲**（电流效率 > 100%、浓度不守恒） | 疑似解析/抽取错误 | 调 04 约束校验器复核 → 拒绝入库或转人工，不静默修数 |
| 综述转引他人数值（secondary） | 非一手来源 | `source_claim_origin=secondary`，策审时尝试回溯原文（§3.2 引文 DOI 网络），回溯成功前不得升 verified |

| 归一对象 | 策略 | 示例 |

## 5. 策审与入库（knowledge_curator）

### 5.1 完备性检查（每篇文献）

| 检查项 | 阈值/判据 | 不通过处置 |
|---|---|---|
| 元数据完备 | 题名/作者/年份/来源/DOI 或稳定 ID 齐备 | 回调研阶段补元数据 |
| 断言非空 | 抽取断言数 ≥ 1，或显式声明“本文无结构化数据” | 归档到观察桶，不入知识面 |
| 数值断言质量 | 100% 数值断言带单位（§4.2 降级表执行后仍留 missing_unit 的比例 = 0） | 转人工修正或整段 hypothesis |
| 出处定位 | 每断言有 locator（页码/T/C 对象 ID） | 无法定位 → 降 hypothesis 并告警 |
| 图表对象 | ChartObject 图注/轴/单位完备，或已标“不可数字化” | 标 `chart_quality=low`，不参与 verified |
| ParsedDoc 分级 | quality_grade ∈ {A, B} 才进入正式面 | C 级人工、D/E 不进 |

### 5.2 冲突检测（与既有图谱断言比较）

对每个新断言，用图查询找「同 subject+property」的既有断言集合（跨文献），按数值做比较：

| 结果类型 | 判据 | 处置 |
|---|---|---|
| 一致 | 新值落入既有值域 [min,max]±容差 或区间重叠 | 归并统计（更新区间/均值/样本数），多源一致可**提升 confidence → high**（01 A.6：多源一致） |
| 工况差异 | 数值不同但 conditions 绑定维度不同（温度/浓度/膜型） | **不算冲突**：按工况区分为多条条件化断言，互不覆盖 |
| 数值冲突 | 同工况域下区间**不交叠** | 进入真值判定（下） |
| 关系/属性矛盾 | 同一关系的布尔/枚举值相反（如“BMED 可否直接处理该进水”yes/no） | 同上 |
| 机理违背 | 新断言违反 L3 硬规则/量纲（04） | 调 04 约束校验器，违规即拒绝或转人工复核 |

**真值判定（仅用于数值冲突）**：按证据强度排序——① 一手实验（含数字化数据、样本量、误差带）＞ ② 权威综述+多源共证 ＞ ③ 单篇报道 ＞ ④ secondary 转引；再叠加来源独立性、期刊可信度、时效性（近 5 年优先）、撤稿状态。可判 → 胜者升权、败者保留历史并标 `superseded`；**不可判 → 双断言挂起人工**（`pending_review` 队列，L0 策审台展示原文段落对比），人工裁决前任何一方都**不得以 verified/high 参与推理**——这是避免“错误自我强化”（08 §8）的关键闸门。

### 5.3 质量评分（与 01/02 对齐）

```
Q(doc)  = w1·P_parse   (ParsedDoc 分级 A/B，B 扣 20%)          // w≈0.25
        + w2·S_schema  (schema 校验一次通过率)                  // w≈0.25
        + w3·E_evidence(出处定位完备率 + 一手来源占比)           // w≈0.30
        + w4·N_novelty (与图谱既有断言重复度，越低越高)          // w≈0.10
        + w5·penalty   (冲突挂起/机理复核/图表 low 每项扣分)     // w≈0.10
```

- 全局置信与 01 A.6 对齐：**verified** = 人工/实验证实（人工抽检通过或案例回流证实）；**high** = 多源一致 + 一手来源 + 无冲突；**medium** = 单源但有单位与工况；**hypothesis** = 缺条件/含推测措辞。仅 verified/high 作为“事实”参与推理，medium 仅作参考展示，hypothesis 仅作待验证假设。
- 低质量文献（Q < 阈值）整体降权：检索命中排后、不参与交叉核验的“多源”计数。

### 5.4 原子入库（存储三载体落库）与版本快照

| 载体（01 A.5 存储三载体 / 08 §2） | 写入内容 | 键/索引 |
|---|---|---|
| 图谱层（SQLite 关系表/JSON 列） | EDDO 事实图谱三元组（实体-属性-值/关系边，含 confidence/quality/版本字段） | subject+property 复合索引（冲突检测用） |
| 向量索引 FAISS | 语料分块向量 + 断言证据卡向量（BGE-M3） | point 携带 ref_id/page/type 供过滤 |
| 本地文件 data/ | USDO JSON（内容寻址）、原始载荷只读指针（A 档/授权 OA） | content-hash 寻址 |
| 结构化库 SQLite | 文献元数据、Assertion 明细、版本/任务/审计、模式注册 | ref_id/version/provenance_id |
| （不设独立时序库） | 数字化 I-V/EIS 序列文件归档 + SQLite 元数据 | series_id + file_ref |

- **事务边界 = 一篇文献**：同批「图谱写入 + 向量 upsert + USDO 落库 + 元数据提交」在同一事务内；失败整体回滚（图谱事务为主，向量库用两阶段/补偿：先图后向量，向量失败则图侧打 `pending_vector` 重放）；
- **幂等**：以 (ref_id, 源指纹 hash) 判重，重复提交仅做 merge/version bump；
- **版本快照**：每次原子提交生成 `KB-version`（对齐 01 §4.4），快照含提交内容 hash 清单，可整体回滚；下游（问答/模型/评测）只读已提交版本；
- **人工抽检口**：抽检策略 = 随机 5%~10% + 高风险 100%（图表数字化文献、冲突挂起、数值密集、secondary 转引）；L0 策审台按文献展示 ParsedDoc、AssertionSet、冲突面板、原文定位，裁决结论（通过/修订/拒绝）写回并影响抽检 KPI（07 看门狗消费：抽检通过率、人工介入率）。

## 6. 反幻觉检索问答侧设计

> 需求来源：R2「基于知识库问答且不产生 AI 幻觉」（01 §1.1）。本节约定知识库问答（含供 RADE proposer 检索使用的同一套检索接口）的工程规则，与 05/07 的对抗与评测形成完整闭环。

### 6.1 语料分块（chunking）策略

| 单元 | 切法 | 理由 |
|---|---|---|
| TableObject | **整表一个 chunk**（caption+headers+units+rows 摘要），可另建行级指针 | 切碎会破坏行列语义与单位上下文 |
| ChartObject | ChartObject 自身为一个 chunk（图元数据+数字化摘要） | 图是一段带坐标系语义的测量载荷，不与正文混切 |
| 文本段落 | 以标题为锚，每 chunk ≤ 512 token + 64 token 重叠 | 语义完整 + 相邻上下文 |
| 断言证据卡 | 以 Assertion 为粒度组装「证据卡 chunk」（陈述+值+单位+工况+出处） | 供声明级精确引用（§6.3） |
| 元数据前缀 | 每 chunk payload 前缀：`[ref_id|page|section|type(文本/表/图/证据卡)]` | 检索结果天然带定位，问答可据此锚定 |

两级检索对象：coarse（整篇摘要向量）→ fine（上述细粒度 chunk），先 coarse 过滤再 fine 精排，控制召回噪声。

### 6.2 混合检索与证据定位

- **三通道融合**（01 L2“三通道”）：① 向量相似（FAISS（可升 Qdrant），BGE-M3 双语，query 先做 EDDO 概念扩展改写）；② 图谱查询（图谱层 SQL/JSON：实体/关系/条件化取值，精确取数与冲突区间统计；演进可用图库）；③ 关键词/BM25（中文分词）。RRF 融合后交 bge-reranker 精排；
- **证据定位**：检索结果 = chunk + 完整 provenance（`ref_id`、页码/对象 ID、句子/单元格指针、confidence、quality、access 链接）。LLM 只允许基于该证据集作答，证据不足走 Abstain（6.3）。

### 6.3 引用锚定生成与 Abstain

**声明级引用锚定**：生成器把答案切成**声明句**，每句带 `(证据类型, ref_id, 定位, confidence)`（证据类型∈{文献,图谱,仿真,实验}，与 01 A.6 一致）：

```
[答] 双极膜电渗析生产酸碱在 25 °C、0.05 mol/L NaCl、20 mA/cm² 工况下
     能耗约 1.4 kWh/m³。(文献, ED2025-0042, T12, high)
     另有单篇报道更低能耗，但工况不同（浓盐水进水），仅作参考。
     (文献, ED2024-0118, p.8 Fig.3, medium)
[待验证] 膜寿命在 2000 h 以上 —— 知识库中仅 hypothesis 级来源，不作事实陈述。
```

语气规则（由 confidence 驱动，禁止越级）：

| 证据状态 | 允许语气 | 反例（禁止） |
|---|---|---|
| verified/high | 陈述语气 + 引用 | 把 medium 说成“已证实” |
| medium（单源） | 必须加“据单篇文献/该值待多源验证” | 单源当多源共识 |
| hypothesis | 只能出现在“待验证假设”区 | 以事实口气复述推测 |
| 数值跨源不一致 | 展示区间与出处，交由用户判断 | 悄悄选一个“看起来对”的 |

**Abstain（证据不足禁答）触发条件**：

1. 检索 top 证据相似度低于阈值，或证据集不足以覆盖问题全部子问；
2. 问题关键数值在图谱中只有 hypothesis/冲突挂起来源；
3. 问题要求文献综述之外的推断且无机理模型可查（04）；
4. 涉机构私有数据而无授权。

Abstain 输出模板（明确、可执行，**绝不编造**）：“知识库证据不足，无法给出有据可依的结论。建议补充：① 检索/订阅 X 数据库（某主题词）；② 设计 Y 实验补测（可转 06 exp_designer）；③ 提供 Z 数据（导入 ERP 后由 validator 校验）。”——同时把“缺什么证据”结构化回传，反哺 §2.6 的 coverage 缺口。

### 6.4 交叉核验与机理约束校验（L3 硬规则对接）

- **多源一致性核验**：答案中的关键数值声明，先向图谱取「同 subject+property 跨文献取值集合」；答案值在集合区间内 → 放行并给出区间；离群/超区间 → 强制修改答案或降级为“待验证并附出处差异”；medium 单源声明强制显式标注（§6.3 语气规则）；
- **机理约束校验器对接（04）**：答案定稿前，把每个数值声明过 L3 硬规则引擎（量纲一致性、电流效率 ≤100%、能量平衡、i ≤ i_lim、Donnan/电中性等，见 04），接口形如 `POST /validator/check(claims[]) → {pass, violations[], suggestions[]}`；违规声明要么重生成，要么降级为 hypothesis 并提示机理冲突——**宁可答得保守，不给违反电化学机理的“漂亮答案”**；
- **答前自检清单**（模型端 checklist + 服务端断言器双保险）：① 每个数值声明是否有锚；② 单位制式一致（分数/百分、m³ 产水基准）；③ 数值量级 sanity（能耗、效率是否在物理范围）；④ 机理硬规则全部通过；⑤ 多源一致或已显式标注单源；⑥ 未覆盖子问题已 Abstain；⑦ 无编造 ref_id（所有引用可查 KB 文献表）。

### 6.5 幻觉率测评点定义（支撑 07 看门狗）

三类幻觉是统一的测评口径（07 看门狗与 RAGAS/自研断言器共用，08 §2 L6）：

| 类 | 定义 | 检测器（自动化） |
|---|---|---|
| H1 声明无证据 | 答案含数值/事实声明但没有锚，或锚与声明内容不匹配（锚错位） | 句-锚对齐解析器：抽取答案中数值声明 → 校验每句 ≥1 条 valid anchor；锚的 ref_id 必须存在于 KB |
| H2 编造文献 | 引用不存在的文献（假 DOI/假标题/张冠李戴） | 引用元数据校验器：ref_id → KB 文献表；DOI → Crossref 存在性校验；标题相似度校验 |
| H3 机理违反 | 数值/结论违反量纲或 L3 硬规则 | 机理约束断言器（同 §6.4 validator 复用在评测端） |

- 度量：golden 测试集（07）上分别计 H1/H2/H3 发生率与总体幻觉率、可引用率、Abstain 率、证据可验证率（抽样人工复核抽查 H2 的“引用真实存在”比例）；
- 上报：每条问答样本的 `(问答id, 声明集, 锚集, 自检清单结果, 类别标注)` 落审计，供 07 看门狗趋势告警与 RAG 回归；
- M1 验收口径：可引用率 ≥ 90%、Abstain 率 > 0（允许说“不知道”）、H2 = 0（编造文献零容忍）。

## 7. 更新与增量：新文献、撤稿/勘误、版本修订

### 7.1 新文献增量入库

- 触发：用户发起 / 期刊 TOC 订阅 / arXiv 每日轮询 / 引用网络发现新引用（某已入库文献被新文献引用且相关性高）/ 案例回流附带的文献；
- 增量路径与首建一致（§1 阶段 A→D），但**复用去重与版本比较**：DOI/title 命中既有记录 → 判断是新版本还是新文献；
- **预印本 → 期刊版**：arXiv 版与 journal 版合并 `versions[]`，以终版语义重抽增量断言（只重抽变化段落），图谱按 §7.3 修订流程落新版本。

### 7.2 撤稿 / 勘误处理

| 事件 | 触发源 | 处置 |
|---|---|---|
| 撤稿（retraction） | Crossref 撤稿标记 / RetractionWatch / 出版社通知（订阅抓取） | 文献状态 → `retracted`；其全部断言 → `archived`（**不再进入任何检索与问答证据面**，历史版本保留以保溯源）；图谱中由这些断言推导出的实体关系联动降级；广播失效事件给问答缓存、04 训练集与 05/07 |
| 勘误（corrigendum） | 出版社/Crossref | 定位受影响断言 → 起草修订集 → 走 §7.3 评审 → 原子提交新版本，旧版保留可回滚 |
| 状态核查 | 周期性（月度）全库复查撤稿标记 | 比对 Crossref 撤稿清单，全量一致性检查 |

### 7.3 已入库内容版本修订流程

```
触发（人工纠错 / 冲突裁决 / 案例回流证实证伪 / 撤稿勘误 / 新增更强证据）
   → knowledge_curator 起草修订集（改哪些断言、依据、evidence 链）
   → 评审：低风险走规则批（高置信+多源+无争议）；高风险走 L0 人工裁决台
   → 原子提交 新 KB 版本（旧版本快照保留，可一键回滚；01 §4.4 append-only + versioned）
   → 事件广播：问答证据缓存失效、04 训练集/约束库更新提示、07 指标与审计记录
```

修订只产生新版本、不物理删除（soft archive），保证“任意对象可回溯到原始证据”（01 §4.1）与 Case 的 append-only 语义（01 A.5）不被破坏。
